# Mini Marketplace – working notes

Event-driven marketplace: Go microservices behind a gin API gateway, a Next.js frontend, Postgres/Redis/Kafka,
deployed with Docker Swarm + Traefik. Full documentation lives in [`docs/`](docs/README.md) (start there; REST reference: `docs/design/04_API_REFERENCE.md`; built vs not: `docs/process/01_IMPLEMENTATION_STATUS.md`; open issues: `docs/planning/01_OPEN_ISSUES.md`; AI plans and datasets: `docs/ai/`, `docs/dataset/`; incident playbooks + agent ground truth: `docs/playbooks/`).

## Layout
```
apps/frontend/        Next.js 14 UI (talks only to the gateway)
services/api-gateway/ REST (gin) → gRPC; JWT auth, RBAC, rate limiting, ownership checks, POST /events tracking
services/auth-service/    accounts, passwords, JWT issue/refresh      gRPC :50051
services/order-service/   cart, checkout (one order per store), order state machine, outbox   gRPC :50052
services/product-service/ catalog/search, inventory (available/reserved/sold + ledger)        gRPC :50053
services/user-service/    buyer/seller profiles, delivery addresses   gRPC :50054
services/analytics-service/ tracking + Kafka events → ClickHouse, scoped reports              gRPC :50055
services/payment-service/ SIMULATED payments (mockpay), webhooks, refunds                     gRPC :50057
services/ops-service/     incidents from Prometheus alerts + append-only audit log (ADR-38)     HTTP :8080 (gateway only, /ops/*)
services/ai-agent/        Python (FastAPI + LangChain) agent: buyer/seller/admin/operator personas, tools = gateway REST via agent token (admin read-only; operator may only propose an ops action)  HTTP :8090 (gateway only); see docs/ai/08_AGENT_BUILD_ROADMAP.md
(every Go service also serves an internal admin HTTP port :8081: /health /healthz /ready /readyz /metrics /version)
shared/               Go module mini-marketplace/shared: ops, events (outbox worker + dead-letter tools), messagequeue/kafkaimpl, reqctx, tracing (ADR-33, ADR-36)
deploy/               infra.yml (postgres, redis, clickhouse, kafka), observability.yml (prometheus + alerts.yml, grafana, loki/vector, tempo), services.yml (traefik + apps), grafana/, prometheus/, traefik/, .env.example
scripts/              check-playbooks.sh, gen-dev-certs.sh, build-images.sh, deploy.sh, teardown.sh, backup-postgres.sh, protogen/gen.sh, dev/chdb_server.py (+gen_traffic.py), e2e/ (outdated)
.github/workflows/    CI
```
Each service is its own Go module (`go.mod`) that imports `shared/` via `replace ../../shared`; run go commands from `services/<name>`, but build images with the repo root as context: `docker build -f services/<name>/Dockerfile .` (or `scripts/build-images.sh`). Test shared code with `cd shared && go test ./...`.
`.pb.go` files are generated by `buf generate` (`services/<svc>/buf.gen.yaml`) or offline with `scripts/protogen/gen.sh <svc>` and copied into the consumers; do not edit them.

## Commands
```bash
# build / vet / test one service (from services/<name>)
go build ./... && go vet ./... && go test ./...
# tests that need Postgres / ClickHouse are skipped unless these are set (a throw-away DB is created per test)
export TEST_POSTGRES_DSN="host=localhost port=5432 user=postgres password=postgres sslmode=disable"
export TEST_CLICKHOUSE_URL="http://127.0.0.1:8123"     # CI uses ClickHouse 24.8; without Docker: pip install chdb && python3 scripts/dev/chdb_server.py --port 8123
scripts/protogen/gen.sh payment-service                # regenerate .pb.go offline (see docs/design/06_PROTOBUF.md)
python3 scripts/datagen/datagen.py synthetic --seed 1 --start 2026-07-01 --end 2026-09-30 --psql "docker exec -i <pg> psql -U postgres -d postgres" --ch-url http://127.0.0.1:8123 --ch-db marketplace --ch-ensure-schema   # fake history (docs/design/07_DATA_PIPELINE.md)
(cd services/analytics-service && go run ./cmd/backfill backfill --from 2026-07-01 --to 2026-09-30 && go run ./cmd/backfill reconcile --from 2026-07-01 --to 2026-09-30)   # PG -> ClickHouse facts + compare; export: python3 scripts/export/export.py --profile otto ...

# local infra + all services (needs deploy/.env; see deploy/.env.example)
cp deploy/.env.example deploy/.env && ./scripts/build-images.sh      # HTTP by default; PUBLIC_SCHEME=https needs ./scripts/gen-dev-certs.sh
docker swarm init
./scripts/deploy.sh            # stacks "marketplace-infra", "marketplace-obs" (Grafana), "marketplace"

# frontend
cd apps/frontend && npm install && npm run dev
```

## Conventions
- Never commit `.env`, keys, certs or binaries (`.gitignore` blocks them); add new settings to the matching `.env.example` (every variable is a real `KEY=value` line, never commented out; no placeholder values; empty = unset; comments go on their own line and only explain; the one exception is a variable where empty differs from unset, e.g. `RECONCILE_PG_DSN`, described in a comment instead).
- Identity comes **only** from the JWT (set by the gateway middleware). Never trust user/buyer/seller IDs, prices, totals or statuses from request bodies.
- Service layer returns `status.Error(codes.X, …)`; the gateway maps gRPC codes to HTTP (`handler/helpers.go`).
- Cross-service side effects go through the transactional **outbox** (DB row + worker → Kafka; `domain_events` in product/order/payment). Consumers must be idempotent. Browser tracking goes gateway → analytics-service over gRPC, not Kafka.
- Auth middleware is attached **per route/group**, never with `router.Use` (a global one made public routes 401). New route ⇒ add it to the table in `api-gateway/internal/router/router_test.go`.
- Money is `NUMERIC(18,2)` in Postgres, `float64` (VND) on the REST/gRPC wire, integer cents in arithmetic (`order-service/internal/service/money.go`); Kafka events carry integer `*_minor` (1/100 VND). Platform timezone is fixed `Asia/Ho_Chi_Minh`.
- Payments are SIMULATED only (never store card data). Analytics revenue = subtotal of orders PAID (online) / DELIVERED (COD) minus refunds.
- Postgres schema changes go through goose migrations in `services/<svc>/migrations/NNNNN_*.sql` (embedded, run at startup, version table `goose_db_version_<svc>`); never add `AutoMigrate`. Pin goose at v3.26.0 (v3.29 needs Go 1.26).
- `X-Request-ID` (HTTP) / `x-request-id` (gRPC metadata) is set by the gateway and propagated by each service's `internal/requestid`; log it, never use it as a Loki label. The id also rides the outbox (`request_id` column, set from the tx context: open transactions with `db.WithContext(ctx)`) and the Kafka header `x-request-id` (`shared/reqctx`; each service calls `reqctx.Use` in `main`). Gateway gRPC calls have deadlines (`GRPC_TIMEOUT_*`), a per-service circuit breaker (`CIRCUIT_*`), and retry only read methods plus the key-idempotent `Checkout` (`idempotentWrites`). Tracing (OTel → Tempo) is on when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; log through zap (stdlib `log` is redirected to JSON).
- Git: never run `git add`/`git commit` unless the user asks; when they do, give one-line commands (one `git add` line, one `git commit -m` line with a single-line message). No `Co-Authored-By` trailer and no "Generated with" line in commits or PR text.
- AI agent: the table `agent/scopes.go` (gateway) is the only source of what an agent token may call (`DefaultScopes` reads, `DefaultActions` proposals; `readOnlyRoles` = admin gets no proposals; operator proposes exactly one thing, `ops_action` = create an ops proposal, ADR-45; RCA loop = LangGraph in `ai-agent/src/ai_agent/rca/` with persona `rca` (read-only: `allow_actions=False`) and `llm.roles.rca`, ADR-46; it reads with a read-only SYSTEM token (`sys` claim, `POST /ai/system-token`, key `AI_SYSTEM_KEY`, only GET `/ops/*`, can never propose; ADR-47) and the operator confirms a draft with their own JWT via `POST /ops/rca/runs/:id/proposal`; UI `/admin/incidents`; its eval is `evals/run_rca_evals.py` (19 cases built from `scripts/e2e/resilience.sh` ground truth); its tool list is filtered to `/ops/` paths (the system token gets 403 elsewhere), `rca.collect_model_calls/collect_tool_calls/max_tool_errors` bound a collect round; log in `docs/ai/11_RCA_BUILD_LOG.md` §16.27-16.35; any model call outside the chat agent must run under `set_run(ctx)` because the OpenCode `x-opencode-session` header is read from that contextvar, or the provider answers 400). A new tool = a row there + a GET route behind `agentOr(...)` + a friendly label in `ai-agent/.../runtime/events.py`. Agents only PROPOSE writes; the user confirms in the UI with their own JWT. Numbers about order rules come from `GET /shop/rules` (tool `get_shop_rules`), never typed into `personas/*/policy.md`. `FEATURE_AI_CHAT/OPS` on without `AI_SERVICE_URL`/`AGENT_TOKEN_KEYS` stops the gateway at start; one chat stream per user (Redis `ai_slot:`). buyer/seller (`Persona.hide_internals`) never see API paths or tool names (model_view label + `guard/leak.py`); a new persona = code + `personas:` and `llm.roles` in BOTH configs (a test checks); `scripts/smoke-ai.sh` after deploy (calls an LLM) and `scripts/smoke-rca-tools.sh` (no LLM: RCA tools with the real system token); finished RCA runs, their events and checkpoints are purged after `rca.retention_days` (30); RCA conclusions are checked deterministically against the collected evidence (`rca/grounding.py`, ADR-50) and LLM provider faults go through `llm/resilience.py` (one retry layer = SDK `max_retries`; breaker per profile; `llm.fallbacks`; CI job `ai-agent` runs pytest + static evals, never a real model; eval split `--split dev|heldout`: tune on dev only). ai-agent tests need Python 3.12 (3.10 cannot stream tokens): `conda activate base_python_3.12` then `cd services/ai-agent && python -m pytest`; proto changes: `scripts/protogen/gen.sh <svc>`.
- AI agent, rules learned the hard way (details: `docs/ai/09_AGENT_BUILD_LOG.md` §16.8-16.17, ADR-44): the privileged ops role is `operator` (renamed from `dev`; `dev` still means the ENVIRONMENT in `APP_ENV`, `config.dev.yaml`, `ENV=dev`, `/admin/dev/payments`, `/dev/tracking`, so never bulk-replace "dev"). List tools filter and sort on the SERVER (empty param = no filter, bad value = 400, never silently ignored) so "top N / this month / over 1M" is ONE call, not paging; a tool query param must be read by a gateway handler (`TestEveryQueryParamOfAToolIsReadByAHandler`); stock sort is store-owner only (public stock is masked "20+"). Per-user daily token cap: `limits.daily_tokens.<persona>` (429 `daily_token_limit`). Buyer/seller (`hide_internals`) never see API paths or tool names. In the chat UI, looked-up data is a fold ("Dữ liệu đã tra cứu (N)"), closed for admin/operator. Changing a tool or param in `scopes.go` fails `TestEveryQueryParamOfAToolIsReadByAHandler`/`TestEvalToolSnapshotIsCurrent` until `go run ./cmd/dump-agent-tools > ../ai-agent/evals/tools.snapshot.json` is rerun and the 422 hand-written eval cases (`services/ai-agent/evals`, `run_evals.py --live` is the only thing that calls an LLM) still validate. ai-agent serves `/metrics` (job `ai-agent`); frontend metrics come from Traefik; ops-service serves `docs/playbooks` at `GET /playbooks` (tools `ops_list_playbooks`/`ops_get_playbook`).
- LLM calls cost money: NEVER run anything that calls a real model (`run_evals.py --live`, `run_rca_evals.py --live`, chat smoke against a real provider, any script using `OPENCODE_API_KEY`/`DEEPSEEK_API_KEY`/`ANTHROPIC_API_KEY`) without asking the user first and getting a go-ahead for that specific run. Earlier approval does not carry over to a later run; say what will run, how many calls, and why. Offline checks (`run_evals.py` without `--live`, pytest) are fine.
- Never name a tool parameter after a Python keyword in the model-facing schema: LangChain silently drops it (`from` was lost until 2026-11-15; see `tools/spec.py` `py_name`).
- Add tests with every behavior change (see `docs/instruction/04_TESTING.md`).
- Demo data only with `SEED_DEMO_DATA=true` (never in production).
