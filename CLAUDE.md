# Mini Marketplace – working notes

Event-driven marketplace: Go microservices behind a gin API gateway, a Next.js frontend, Postgres/Redis/Kafka,
deployed with Docker Swarm + Traefik. Full documentation lives in [`docs/`](docs/README.md) (start there; REST reference: `docs/design/04_API_REFERENCE.md`; built vs not: `docs/process/01_IMPLEMENTATION_STATUS.md`; open issues: `docs/planning/01_OPEN_ISSUES.md`; AI plans and datasets: `docs/ai/`, `docs/dataset/`).

## Layout
```
apps/frontend/        Next.js 14 UI (talks only to the gateway)
services/api-gateway/ REST (gin) → gRPC; JWT auth, RBAC, rate limiting, ownership checks, POST /events tracking
services/auth-service/    accounts, passwords, JWT issue/refresh      gRPC :50051
services/order-service/   cart, checkout (one order per store), order state machine, outbox   gRPC :50052
services/product-service/ catalog/search, inventory (available/reserved/sold + ledger)        gRPC :50053
services/user-service/    buyer/seller profiles, delivery addresses   gRPC :50054
services/analytics-service/ tracking + Kafka events → ClickHouse, scoped reports              gRPC :50055
services/payment-service/ SIMULATED payments (mockpay), webhooks, refunds                     gRPC :50057
(every Go service also serves an internal admin HTTP port :8081: /health /healthz /ready /readyz /metrics /version)
deploy/               infra.yml (postgres, redis, clickhouse, kafka), observability.yml (prometheus, grafana), services.yml (traefik + apps), grafana/, prometheus/, traefik/, .env.example
scripts/              gen-dev-certs.sh, build-images.sh, deploy.sh, protogen/gen.sh, dev/chdb_server.py (+gen_traffic.py), e2e/ (outdated)
.github/workflows/    CI
```
Each service is its own Go module (`go.mod`), built from its own directory (`docker build services/<name>`).
`.pb.go` files are generated by `buf generate` (`services/<svc>/buf.gen.yaml`) or offline with `scripts/protogen/gen.sh <svc>` and copied into the consumers; do not edit them.

## Commands
```bash
# build / vet / test one service (from services/<name>)
go build ./... && go vet ./... && go test ./...
# tests that need Postgres / ClickHouse are skipped unless these are set (a throw-away DB is created per test)
export TEST_POSTGRES_DSN="host=localhost port=5432 user=postgres password=postgres sslmode=disable"
export TEST_CLICKHOUSE_URL="http://127.0.0.1:8123"     # CI uses ClickHouse 24.8; without Docker: pip install chdb && python3 scripts/dev/chdb_server.py --port 8123
scripts/protogen/gen.sh payment-service                # regenerate .pb.go offline (see docs/design/06_PROTOBUF.md)
python3 scripts/datagen/datagen.py synthetic --seed 1 --start 2026-07-01 --end 2026-09-30 --psql "docker exec -i <pg> psql -U postgres -d postgres" --ch-url http://127.0.0.1:8123 --ch-db marketplace --ch-ensure-schema   # fake history (docs/design/07_DATA_PIPELINE.md)
(cd services/analytics-service && go run ./cmd/backfill backfill --from 2026-07-01 --to 2026-09-30 && go run ./cmd/backfill reconcile --from 2026-07-01 --to 2026-09-30)   # PG -> ClickHouse facts + compare; export: python3 scripts/export/export.py --profile otto ...

# local infra + all services (needs deploy/.env; see deploy/.env.example)
cp deploy/.env.example deploy/.env && ./scripts/gen-dev-certs.sh && ./scripts/build-images.sh
docker swarm init
./scripts/deploy.sh            # stacks "marketplace-infra", "marketplace-obs" (Grafana), "marketplace"

# frontend
cd apps/frontend && npm install && npm run dev
```

## Conventions
- Never commit `.env`, keys, certs or binaries (`.gitignore` blocks them); add new settings to the matching `.env.example`.
- Identity comes **only** from the JWT (set by the gateway middleware). Never trust user/buyer/seller IDs, prices, totals or statuses from request bodies.
- Service layer returns `status.Error(codes.X, …)`; the gateway maps gRPC codes to HTTP (`handler/helpers.go`).
- Cross-service side effects go through the transactional **outbox** (DB row + worker → Kafka; `domain_events` in product/order/payment). Consumers must be idempotent. Browser tracking goes gateway → analytics-service over gRPC, not Kafka.
- Auth middleware is attached **per route/group**, never with `router.Use` (a global one made public routes 401). New route ⇒ add it to the table in `api-gateway/internal/router/router_test.go`.
- Money is `NUMERIC(18,2)` in Postgres, `float64` (VND) on the REST/gRPC wire, integer cents in arithmetic (`order-service/internal/service/money.go`); Kafka events carry integer `*_minor` (1/100 VND). Platform timezone is fixed `Asia/Ho_Chi_Minh`.
- Payments are SIMULATED only (never store card data). Analytics revenue = subtotal of orders PAID (online) / DELIVERED (COD) minus refunds.
- Postgres schema changes go through goose migrations in `services/<svc>/migrations/NNNNN_*.sql` (embedded, run at startup, version table `goose_db_version_<svc>`); never add `AutoMigrate`. Pin goose at v3.26.0 (v3.29 needs Go 1.26).
- `X-Request-ID` (HTTP) / `x-request-id` (gRPC metadata) is set by the gateway and propagated by each service's `internal/requestid`; log it, never use it as a Loki label. Gateway gRPC calls have deadlines (`GRPC_TIMEOUT_*`) and retry only read methods.
- Add tests with every behavior change (see `docs/instruction/04_TESTING.md`).
- Demo data only with `SEED_DEMO_DATA=true` (never in production).
